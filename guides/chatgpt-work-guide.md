# ChatGPT Work 怎么用？Chat、Work、Codex、文件与长任务完整指南

**直接答案：**需要快速提问、搜索或讨论时选择 **Chat**；需要根据多份资料完成一项长任务并交付文档、表格、演示文稿或报告时选择 **Work**；需要编写代码、运行测试或处理软件仓库时选择 **Codex**。开始 Work 任务前，先确认当前账号确实显示 Work，再明确交付物、提供必要资料、限定不能改变的内容，并在结果交付后逐项验收。

OpenAI 当前说明，Work 在网页和移动端面向符合条件的付费计划开放，桌面端是否可用还会受到计划和工作区权限影响。如果你的账号没有显示 Work，不要因为一篇旧教程就重新付款；先核对账号、计划、应用版本和工作区设置。

> 本文只解决“ChatGPT Work 应该怎样选择、设置和验收”的问题。已有成功扣款、待处理交易或有效订阅时，不要为了寻找 Work 入口再次购买。

## 第一步：先判断应该使用 Chat、Work 还是 Codex

先选对入口，可以避免把简单问题变成长任务，也可以避免用 Work 处理本应交给 Codex 的软件开发操作。

| 你的目标 | 应选入口 | 完成后应该得到什么 |
|---|---|---|
| 问一个问题、搜索资料、讨论想法或快速修改文字 | Chat | 一段回答、建议或短内容 |
| 汇总多份资料，完成文档、表格、演示文稿、报告、分析或 Site | Work | 可继续修改和验收的完整交付物 |
| 编写或调试代码、运行命令和测试、检查仓库差异 | Codex | 代码修改、命令结果、测试结果或技术说明 |

如果任务只需要几轮对话就能完成，先使用 Chat。只有任务包含多个步骤、需要中途确认方向，或者最终必须交付一个完整文件时，再切换到 Work。

Codex 是独立的软件开发入口。它在桌面端拥有单独的视图和历史记录，不能在网页或移动端直接作为可选模式使用。需要学习 Codex App、CLI 或 IDE 的用户，可以阅读[ChatGPT Plus / Pro 使用 Codex 指南]({{ '/guides/chatgpt-codex-app-cli-ide/' | relative_url }})。

## 第二步：开始前完成 3 项准备

### 1. 确认账号、计划和使用位置

先在 ChatGPT 中打开个人资料或计划页面，确认：

- 当前登录方式，例如 Google、Apple、Microsoft 或邮箱；
- 当前账号是否显示正确的会员计划；
- 网页、移动端或桌面端是否能够看到 **Work**；
- 如果使用单位工作区，管理员是否允许当前角色使用 Work Cloud 或 Work Local。

**预期结果：**当前账号显示 Work，并且你知道本次任务是在云端还是本地运行。

如果网页端有 Work，但桌面端不能打开本地文件，先让工作区管理员检查权限。OpenAI 当前说明，云端 Work 和本地 Work 的权限可能在不同时间生效；此时不应退出原订阅后重新购买。

### 2. 只准备任务需要的资料

把资料分成“可以交给 Work”和“不能交给 Work”两类。可以提供公开资料、已获授权的内部文件和完成任务所必需的内容；不要上传密码、验证码、恢复码、私钥、完整 Cookie、ChatGPT session 或未脱敏的客户资料。

使用桌面端本地文件夹时，只打开本次任务需要的目录。不要直接授权整个桌面、用户主目录或包含大量私人文件的位置。

### 3. 先写清楚最终交付物

在发送任务前，用一句话补齐下面五项：

1. 要完成什么；
2. 给谁使用；
3. 使用哪些资料；
4. 输出什么格式、保存到哪里；
5. 哪些内容绝对不能改变。

例如，可以直接发送下面这段指令：

> 请根据我上传的三份月度数据，为运营负责人制作一份月报。
>
> 输出为包含“摘要、趋势、异常、下月动作”四部分的文档，并另外生成一张汇总表。
>
> 所有数字必须来自附件；不要虚构缺失数据；不要改变原表中的公式和列名。
>
> 完成后列出你做过的检查，并标出仍需要我确认的地方。

这一步决定 Work 能否交付可验收的结果。只说“帮我做一份月报”，通常无法约束数据来源、结构和检查标准。

## 第三步：在网页或手机上启动 Work

网页和移动端的 Work 在云端运行，适合使用上传文件、Projects 或已连接的应用完成任务。

### 操作流程

1. 打开 ChatGPT，并确认登录的是前面核对过的账号；
2. 在页面顶部或模式选择位置选择 **Work**；
3. 新建一个 Work 对话，或者打开已有 Project；
4. 添加本次任务需要的文件和背景资料；
5. 写明交付物、输出格式、限制条件和验收标准；
6. 任务执行时查看进度，回答必要问题，并在重要操作前阅读批准内容；
7. 收到结果后，不要直接使用，先按本文后面的验收清单检查。

**预期结果：**Work 能说明它正在处理哪些资料、准备交付什么，并在需要补充信息或批准操作时向你提问。

如果页面没有 Work，依次检查当前账号、计划、应用版本和工作区权限。确认这些信息后入口仍不存在，再联系 OpenAI 支持或工作区管理员；不要反复退出登录，也不要重新订阅。

## 第四步：在桌面端选择云端任务还是本地任务

桌面应用同时包含 ChatGPT 和 Codex。进入 ChatGPT 后，才可以在 **Chat** 与 **Work** 之间切换。

### 操作流程

1. 打开当前版本的 ChatGPT 桌面应用并登录；
2. 点击左上角入口，选择 **ChatGPT**，不要误选 Codex；
3. 在页面顶部选择 **Work**；
4. 要继续云端任务时，新建对话或打开现有 Project；
5. 要处理电脑文件时，只在账号和工作区允许的情况下打开目标文件夹；
6. 系统请求文件、应用、麦克风或辅助功能权限时，先确认是否与当前任务直接相关，再决定是否允许。

云端 Work 对话可以在网页、手机和桌面端之间同步。本地对话及其输出通常只保留在当前电脑，不会自动出现在网页或手机上。

**停止条件：**如果文件选择器打开了错误目录，或者批准卡片包含任务之外的文件和操作，立即取消，不要让任务继续执行。

## 第五步：用 Project 保存长期任务的上下文

Project 用来把同一项长期工作的文件、指令和多次对话放在一起。OpenAI 当前说明，Projects 对免费和付费计划都开放；这不代表每个计划都一定拥有 Work。

### 建立 Project

1. 在 ChatGPT 侧边栏点击 **New project**；
2. 输入能说明用途的名称，例如“2026 年运营月报”；
3. 添加已获授权的参考文件；
4. 打开 Project 右上角菜单，进入 **Project settings**；
5. 写入只适用于该项目的固定要求，例如数据来源、语气、表格结构和禁改内容；
6. 回到 Project，选择 **Work** 开始新任务。

Project instructions 会覆盖全局自定义指令，因此不要把两个项目互相矛盾的要求放进全局设置。项目资料发生变化时，也应先更新来源文件，再让 Work 继续处理。

**预期结果：**在同一个 Project 中新建 Work 对话时，Work 能使用该项目的文件和指令，不需要每次重复解释完整背景。

## 第六步：创建文档、表格和演示文稿

OpenAI 当前说明，Work 可以创建或编辑文档、表格、演示文稿、报告和分析。具体文件类型和操作能力会受到计划、工作区设置和使用位置影响。

### 通用操作顺序

1. 说明文件用途和读者；
2. 上传或连接可信的源资料；
3. 指定输出格式和保存位置；
4. 列出不能改变的公式、版式、品牌、语气、幻灯片顺序或表格结构；
5. 让 Work 先给出结构，再生成完整文件；
6. 打开成品，检查数字、引用、公式、图表和格式；
7. 把具体问题返回同一对话修改，直到通过验收。

### 不同办公文件需要额外说明什么

| 文件类型 | 提示词至少写清什么 | 验收重点 |
|---|---|---|
| 文档或报告 | 章节、读者、语气、引用格式 | 事实、引用、标题层级和遗漏项 |
| 表格 | 工作表名称、列、公式、图表和数据来源 | 公式、单位、总计、筛选范围和异常值 |
| 演示文稿 | 章节、页数、页面类型、品牌和演讲场景 | 每页结论、文字溢出、图表可读性和顺序 |

连接相应 Google Workspace 应用后，Work 可以在支持的账号中创建或编辑 Google Docs、Sheets 和 Slides。ChatGPT 要求选择账号、文件或批准写入时，应先核对目标位置。

Work 可以生成电子表格文件；如果需要直接控制已经打开的 Microsoft Excel 工作簿，OpenAI 当前流程是使用 ChatGPT for Excel 加载项，并在桌面端 Codex 中调用 `@Microsoft Excel`。PowerPoint 不属于 Work 桌面端首发的直接控制流程，因此不要把“能生成演示文稿”理解为“必然能直接控制本机 PowerPoint”。

## 第七步：用 Scheduled Tasks 处理定时或监测任务

Scheduled Tasks 适合提醒、定期简报和变化监测。它与 Codex automation 不是同一个功能。

### 创建与管理流程

1. 在 ChatGPT 侧边栏打开 **Scheduled**；
2. 点击创建任务，或者在 Work 中明确提出一次性、重复或监测要求；
3. 写清运行时间、时区、重复频率和停止条件；
4. 写清每次结果需要包含哪些字段，以及没有变化时是否通知；
5. 在 ChatGPT 通知设置中选择 Push、Email 或两者；
6. 保存后检查下次运行时间；
7. 从 Scheduled 页面查看结果，并按需要暂停、恢复、编辑或删除任务。

例如，可以直接发送下面这段指令：

> 每周一上午 9 点检查 OpenAI 官方发布页。
>
> 只在出现与 ChatGPT Work 有关的新公告时通知我，并提供标题、发布日期和官方链接。
>
> 如果没有相关更新，不要生成重复摘要。

### 两个容易出错的边界

- 在包含文件的 Project 中创建 Scheduled Task，不代表任务可以读取这些 Project 文件。OpenAI 当前明确说明，Scheduled Task 不能访问该 Project 中的文件；
- Scheduled Tasks 不在 Codex 中管理。桌面端应先选择 ChatGPT，再从侧边栏进入 Scheduled。

任务的可用模型、活跃任务数量和运行频率受计划及账号实时规则限制。达到上限时，先暂停、删除或等待现有任务完成，不要因此重新购买订阅。删除与任务关联的对话会使该任务自动暂停。

## 第八步：连接应用前先设置权限

Apps 可以让 ChatGPT读取连接服务中的信息，部分应用还可以创建、修改或发送内容。连接应用不会让 ChatGPT自动获得所有权限，但用户仍需要核对授权范围和每次操作。

### 新用户建议这样设置

1. 打开个人资料菜单，进入 **Settings → Apps**；
2. 只连接当前任务真正需要的应用；
3. 在 **App Preferences → Ask permission** 中选择权限；
4. 第一次使用建议选择 **Always ask**，或至少选择 **Any changes**；
5. 每次出现批准卡片时，检查应用、目标文件、接收方和具体动作；
6. 任务结束后，不再需要的应用从 **Settings → Apps** 中断开。

OpenAI 当前将 **Important actions** 作为默认选项；它会在发送消息、删除内容、购买、退款、上传文件或改变权限等重要动作前请求批准。**Never ask** 允许应用在更少确认的情况下执行操作，风险更高，不适合第一次连接应用的用户。

个人 Free、Plus、Go 和 Pro 账号在开启 **Improve the model for everyone** 时，OpenAI 可能使用从应用访问的信息改进模型。需要关闭时，进入 **Settings → Data Controls**，关闭该选项。关闭后，对话仍会保留在历史记录中，但不会用于改进模型；第三方应用如何处理数据仍受其自身条款和隐私政策约束。

## 一个完整示例：从零完成月度运营报告

下面的流程把入口选择、Project、Work 和验收连在一起。

### 阶段 1：建立工作区

新建“运营月报”Project，添加已脱敏的月度数据和品牌模板。在 Project settings 中写明统计口径、受众、语气和不能改变的字段。

### 阶段 2：让 Work 先规划

选择 Work，要求它先列出报告结构、所需数据和缺失项，暂时不要生成成品。检查结构后，补齐能够提供的资料；无法提供的内容明确标记为“缺失”，禁止推测。

### 阶段 3：生成交付物

要求 Work 创建一份报告和一张汇总表，并写明输出格式、命名方式和保存位置。生成后逐项检查总数、同比环比、公式、图表标签和来源。

### 阶段 4：修改并验收

把错误精确指出，例如“第二张表的转化率分母应使用有效访问量，请重新计算并列出公式”。修改完成后下载或打开最终文件，按照原始数据再核对一次。

### 阶段 5：安排下一次工作

Scheduled Task 不能读取 Project 文件，所以不要让它在后台自动处理下个月上传到 Project 的表格。可以建立一条“每月 2 日提醒我更新运营月报资料”的任务；收到提醒后，再由用户进入 Project 上传新资料并启动 Work。

## 常见异常按什么顺序排查

| 现象 | 先检查什么 | 正确下一步 |
|---|---|---|
| 页面没有 Work | 当前账号、计划、应用版本和工作区权限 | 用原账号重新核对；单位账号联系管理员；不要重新购买 |
| 网页有 Work，桌面端不能使用本地文件 | Work Local 是否对当前角色开放 | 联系工作区管理员确认权限，并等待权限同步后再测试 |
| Work 使用了错误资料 | 是否进入了错误 Project，或上传了旧文件 | 停止任务，核对 Project 和来源文件，再从正确上下文重新开始 |
| 文件没有出现在 Library | 任务是在云端、本地还是 Temporary Chat 中执行 | 到本地输出目录查找；Temporary Chat 文件不会保存到 Library |
| Scheduled Task 读不到 Project 文件 | 任务是否依赖 Project 上传文件 | 不要重复运行；改为提醒用户回 Project 手动启动 Work |
| 应用没有按预期执行 | 应用是否已连接、当前权限和管理员设置 | 在 Settings → Apps 核对；需要写入时查看批准卡片 |
| Work 提示达到用量限制 | 计划是否有效、账号页面显示的用量和重置时间 | 按实时页面等待或调整任务；不要把用量耗尽当成订阅失效 |
| 官方页面显示 Free | 是否登录了原购买账号，是否已有扣款或待处理交易 | 进入[已付款仍显示 Free 排查]({{ '/guides/chatgpt-paid-but-still-free/' | relative_url }})，停止重复付款 |

## 问题应由谁处理

| 问题 | 责任方 |
|---|---|
| Work 入口、云端任务、Library、账号计划或官方错误 | OpenAI 支持 |
| 单位工作区的 Work Cloud、Work Local、Apps 或角色权限 | 工作区管理员 |
| Google Workspace、Microsoft 或其他连接应用的服务异常 | 对应应用提供方；同时检查 ChatGPT 连接状态 |
| ChongGrok 卡密、核销记录或客服协助订单 | ChongGrok 售后 |

联系支持前，保存问题时间、当前使用位置、登录方式、计划页面、错误原文和已经完成的步骤。截图应遮住邮箱、订单号、文件内容、session、Cookie 和其他敏感信息。

## 什么时候才需要查看新的会员方案

如果账号已有有效订阅、已经成功扣款或存在待处理交易，应先处理账号、权限或用量问题，**不要再次购买**。Work 没有出现在当前账号中，也不能单独证明付款失败。

只有确认当前账号没有有效订阅、没有待处理付款，也没有需要继续处理的原订单，并且官方实时页面说明目标计划包含所需 Work 能力时，才考虑新的会员方案。ChongGrok 当前 ChatGPT 方案与交付规则见 [chonggrok.com/chatgpt](https://chonggrok.com/chatgpt)。

## 完成验收清单

完成一次 Work 任务后，逐项确认：

- 使用的是正确 ChatGPT 账号和目标 Project；
- Work 只访问了本次任务需要的文件和应用；
- 交付物格式、保存位置和命名正确；
- 数字、公式、引用和关键结论已经人工核对；
- 没有虚构缺失资料；
- 重要外部操作都经过确认；
- 不再需要的应用权限已经撤销；
- 本地文件和云端文件的位置已经记录；
- Scheduled Task 不依赖它无法访问的 Project 文件。

- 不把 session、私钥、完整 Cookie 或生产环境令牌交给 Work；
- 不在未经授权的情况下上传客户、公司或个人敏感资料；
- Apps 的数据处理还受第三方条款和隐私政策约束；
- ChatGPT 会员不等于 OpenAI API 额度，ChongGrok 不提供 API 充值；
- ChongGrok 与 OpenAI 没有隶属、授权或官方合作关系；

- AI 生成的文件、分析和自动化操作都需要人工验收，任何线上服务都不是零风险。

## 常见问题

### ChatGPT Work 和普通 Chat 有什么区别？

Chat 适合快速问答、搜索、讨论和短内容；Work 适合需要多个步骤、持续检查进度并最终交付文档、表格、演示文稿、报告或其他成品的任务。

### ChatGPT Work 和 Codex 应该选哪个？

制作报告、分析资料或交付办公文件时选 Work；编写代码、运行测试、处理仓库或使用开发工具时选 Codex。Codex 的历史记录与 Chat 和 Work 分开，也不能在网页或移动端直接作为可选模式使用。

### 为什么我的 ChatGPT 里没有 Work？

先确认登录的是正确账号，再检查当前计划、应用版本和工作区权限。OpenAI 当前说明，网页和移动端 Work 面向符合条件的付费计划；桌面端还取决于计划和工作区设置。是否可用以账号实时界面为准。

### ChatGPT Work 可以直接读取电脑里的文件吗？

网页和移动端 Work 不能直接读取电脑本地文件。符合条件的桌面端账号可以在获得授权后打开本地文件夹；只应授权当前任务需要的目录。本地对话及输出通常不会自动同步到网页或手机。

### Scheduled Tasks 可以读取 Project 里上传的文件吗？

不能依赖这种方式。OpenAI 当前说明，在含有文件的 Project 中创建 Scheduled Task 时，该任务不能访问这些 Project 文件。可以把任务改成定时提醒，收到提醒后再进入 Project 启动 Work。

### Work 创建的文件为什么没有出现在 Library？

云端 Work 创建的文件可能在支持时保存到 Library；本地桌面输出通常留在本地文件夹，Temporary Chat 中创建的文件也不会保存到 Library。先确认任务是在云端、本地还是 Temporary Chat 中完成。
