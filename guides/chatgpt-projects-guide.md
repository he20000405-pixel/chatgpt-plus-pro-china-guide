# ChatGPT Projects 怎么用？创建项目、上传文件、设置记忆与共享完整指南

**直接答案：**在 ChatGPT 左侧边栏点击 **New project**，创建项目后依次设置项目指令、记忆范围和参考资料，再从项目内新建聊天开始工作。Projects 对 Free 和付费计划都开放；Plus 或 Pro 不是创建项目的前提，主要差异在文件数量、协作者上限和可用工具。

Project 适合需要持续推进的任务，例如长期写作、课程学习、资料研究或每周报告。它把相关聊天、文件和项目指令放在同一个空间中，避免每次新建聊天都重新解释背景。

> 本文只解决 ChatGPT Projects 的创建、资料管理、记忆、共享和排障问题。页面名称可能随版本调整；操作时以当前账号实际显示的按钮为准。

## 先判断：这项任务是否应该使用 Project

不要把所有聊天都塞进一个项目。先根据任务是否需要长期背景、多人共享或反复使用资料来选择入口。

| 你的任务 | 建议入口 | 原因 |
|---|---|---|
| 只问一次、无需保留背景 | 普通聊天 | 创建项目会增加整理成本 |
| 围绕同一主题持续数天或数周 | Project | 聊天、文件和指令可以集中管理 |
| 多人需要查看同一批资料并继续讨论 | Shared Project | 成员可以在同一项目中查看资料和聊天 |
| 想把一套固定知识和工具重复提供给不同场景 | GPT | GPT 更适合复用相对固定的知识和行为 |
| 只想进行一次不使用个性化记忆的对话 | Temporary Chat | Temporary Chat 不会加入 Project，也不能移入 Project |

如果任务会不断增加文件、产生多个对话，或需要以后继续使用同一套背景，Project 通常比单个长对话更清楚。

## 开始前准备 4 项内容

创建项目之前先准备好以下内容，可以减少后续反复调整。

1. **项目目标：**用一句话写清最终要完成什么，例如“根据公司现有资料，每周生成一次运营摘要”。
2. **资料范围：**整理真正需要的 PDF、表格、文档、图片或文本，不要一次上传整个硬盘。
3. **输出规则：**确定语言、格式、长度、引用方式和必须保留的字段。
4. **隐私边界：**删除密码、验证码、恢复码、银行卡资料、session 和不应向协作者公开的内容。

准备完成后，再按下面的顺序操作。每一步都要先确认结果正确，再进入下一步。

## 第一步：创建一个新的 Project

1. 登录 [ChatGPT](https://chatgpt.com/)，确认当前是自己的目标账号；
2. 在左侧边栏点击 **New project**；
3. 输入能说明用途的名称，例如“2026 内容计划”或“课程复习资料”；
4. 选择容易识别的图标和颜色；
5. 打开新项目，确认项目名称已经出现在侧边栏。

**预期结果：**进入一个独立项目页面，可以看到项目聊天区和资料来源区域。

如果没有 **New project**：

- 先在网页版检查同一账号；
- 手机端更新 ChatGPT App 后重新登录；
- Business、Enterprise 或 Edu 工作区用户还要确认管理员是否关闭了 Projects；
- 仍没有入口时，不要因为这个问题重复购买会员，应以账号当前功能开放状态为准。

## 第二步：选择项目记忆范围

项目记忆决定 ChatGPT 可以从哪些历史对话中获取背景。设置错误时，回答可能引用项目外内容，或无法利用项目内以前的讨论。

打开项目右上角三点菜单，进入 **Project settings → Memory**，然后根据需要选择：

| 记忆方式 | 会引用什么 | 适合什么场景 |
|---|---|---|
| Default memory | 按计划和账号设置使用项目内资料，也可能引用项目外聊天和个人记忆 | 日常工作，希望继续使用个人偏好和已有背景 |
| Project-only memory | 只引用同一项目内的聊天；不读取项目外聊天和个人已保存记忆 | 独立客户项目、敏感任务或需要严格隔离背景的工作 |

选择后点击 **Save**。OpenAI 当前说明，记忆设置变化可能需要数小时才完全生效，因此保存后不要连续切换多次。

还要检查个人设置：

1. 打开 `Settings → Personalization → Memory`；
2. 对非 Enterprise 计划，确认 **Reference saved memories** 和 **Reference chat history** 已按你的需要开启；
3. 回到项目，新建一个测试聊天，询问“这个项目的目标是什么？”；
4. 如果回答引用了不应出现的项目外信息，切换为 Project-only memory，并检查项目中已有聊天和文件。

**重要边界：**项目一旦共享，会自动使用 Project-only memory。共享后不能再切回 Default memory，也不会读取成员在项目外的个人记忆和自定义指令。

## 第三步：填写项目指令

项目指令只在当前项目中生效，并会覆盖全局 Custom Instructions。它应该说明工作方式，而不是堆积全部背景资料。

1. 打开项目右上角三点菜单；
2. 选择 **Project settings**；
3. 在项目指令中填写目标、资料优先级和输出要求；
4. 保存后新建聊天进行验证。

可以使用下面的简洁模板：

> **项目目标：**根据项目资料完成每周运营摘要。  
> **资料优先级：**先使用项目文件；信息不足时明确说明，不自行补写数字。  
> **输出格式：**先给结论，再列依据、待确认事项和下一步。  
> **引用要求：**涉及数字时写明文件名和对应日期。  
> **沟通方式：**关键信息缺失时先提问，不直接假设。

**预期结果：**新建聊天后，回答应自动遵循上述格式，不需要每次重复粘贴要求。

如果回答仍使用全局指令的语气，先确认项目指令已经保存，再新建一个项目聊天测试。不要用已经生成的旧回答判断新设置是否生效。

## 第四步：上传并验收项目文件

在项目的资料来源区域选择添加文件，可以上传 PDF、电子表格、文档、图片，或直接粘贴文本。

1. 点击 **Add source**、上传按钮或当前页面对应入口；
2. 先上传一份代表性文件，不要一次加入全部资料；
3. 上传完成后，在来源列表中打开文件；
4. 确认文件名、页数或表格内容可以正常预览；
5. 新建聊天，让 ChatGPT 列出文件标题、日期、三项关键内容和无法读取的部分；
6. 对照原文件验收，确认无误后再上传剩余资料。

按 OpenAI 在 2026 年 8 月 15 日的官方说明，当前 Projects 文件数量为：

| 计划 | 每个项目文件数 | 单次上传数量 |
|---|---:|---:|
| Free | 5 | 最多 10 个 |
| Go、Plus | 25 | 最多 10 个 |
| Edu、Pro、Business、Enterprise | 40 | 最多 10 个 |

限制可能变化，应以 Projects 官方页面和当前账号提示为准。同名文件上传时，页面可能让你选择 **Upload anyway** 或 **Skip**；前者会保留两个文件，后者只跳过同名文件。

### 文件上传失败时按这个顺序处理

1. 确认当前项目是否已经达到文件数量上限；
2. 将一次上传数量减少到 10 个以内；
3. 删除不再需要的旧文件，或把任务拆成多个项目；
4. 检查文件能否在本地正常打开，再重新上传；
5. 查看 [OpenAI Status](https://status.openai.com/) 是否存在文件服务故障；
6. 仍失败时保存错误提示、时间、文件类型和账号计划，再联系 OpenAI 支持。

不要为了绕过上限反复上传同一文件。这样会增加重复来源，也可能让后续回答引用错误版本。

## 第五步：添加 Google Drive、Slack 或已连接应用

Projects 支持把 Google Drive 文件或文件夹链接、Slack 频道链接添加为项目来源。该功能可能要求先连接对应应用并完成授权。

1. 打开一个私人项目；
2. 在来源区域选择 **Add source**；
3. 粘贴 Google Drive 文件、文件夹或 Slack 频道链接；
4. 页面要求连接应用时，确认授权的是正确账号；
5. 只授予完成任务所需的权限；
6. 添加后让 ChatGPT 列出它实际能访问的资料名称，再对照原应用核验。

Google Drive 应用在 Project 中可以搜索和读取相关文件，但 OpenAI 当前说明它不会在项目内预先同步全部内容。资料更新后，重新查询并核对日期，不要默认 ChatGPT 已经读取最新版本。

也可以在项目聊天中调用已经连接的 Apps。ChatGPT 如果准备搜索项目外内容，可能先要求确认；阅读确认信息后再允许，不要把它当成普通项目文件的自动延伸。

## 第六步：把已有聊天移入 Project

已经进行了一半的普通聊天，不需要从头复制内容。

1. 在侧边栏找到目标聊天；
2. 将聊天拖到项目名称上，或打开聊天菜单；
3. 选择 **Move to project**；
4. 打开项目，确认聊天已经出现在项目中；
5. 继续提问，检查回答是否开始使用项目指令和项目文件。

移入后，聊天会继承项目指令和文件背景。需要移出时，从聊天菜单选择 **Remove**。

以下两类聊天不能这样处理：

- 由 GPT 创建的聊天不能移入 Project；
- Temporary Chat 不能加入 Project。

如果菜单中没有 **Move to project**，不要复制整段聊天到多个项目。应在目标项目中新建聊天，只粘贴经过整理的必要背景。

## 第七步：完成第一次项目任务并验收

项目搭好后，先做一个范围小、容易核对的任务。这样可以验证文件、指令和记忆是否都在正确工作。

示例指令：

> 请只根据当前项目文件，整理一份 300 字摘要。  
> 每项结论后标注文件名和日期。  
> 资料没有说明的内容写“项目资料未提供”，不要自行补充。  
> 最后列出还需要我确认的 3 个问题。

按下面的清单验收：

- 是否使用了正确项目中的文件；
- 是否遵循项目指令中的输出格式；
- 是否把不确定内容明确标出；
- 是否引用了正确文件名和日期；
- 是否错误引用了项目外聊天；
- 新建第二个聊天后，是否仍能理解同一项目目标。

其中任何一项不符合，都先修正项目指令、记忆设置或来源文件。不要在错误配置上继续生成大量内容。

## 第八步：共享 Project，并选择正确权限

确认项目资料可以向他人公开后，再点击右上角 **Share**。不要先分享，再回头清理敏感文件。

个人计划当前可以邀请指定人员；界面提供 **Anyone with a link** 时，也可以让持有链接且已登录 ChatGPT 的用户加入。邀请前需要选择权限：

| 权限 | 对方可以做什么 | 对方不能做什么 |
|---|---|---|
| Chat | 查看并使用项目聊天、文件和指令 | 不能邀请其他成员，也不能修改项目资料 |
| Edit | 更新项目指令、上传或删除文件、邀请成员 | 不能移除已有成员；项目所有者仍保留完整控制权 |

当前协作者数量上限为：Free 5 人，Plus/Go 10 人，Pro 100 人；Business、Enterprise 和 Edu 的工作区共享规则还受管理员设置影响。

共享前必须知道：

- 项目成员可以查看并下载项目文件；
- 成员可以看到项目中的聊天和当前成员；
- 共享后项目自动切换为 Project-only memory；
- 项目不会读取成员在项目外的个人记忆或 Custom Instructions；
- 只想让别人阅读一段结果时，应分享单个聊天，而不是整个项目。

共享单个聊天只会公开该聊天在分享时已有的内容，不会公开其他项目聊天、文件和指令。含客户资料、合同或内部文件时，优先选择范围更小的分享方式。

## 第九步：保存成果、移除资料与删除项目

ChatGPT 生成了以后需要复用的摘要、决策记录或草稿时，可以从回答菜单选择 **Save to project** 或 **Add to project sources**。保存后在项目来源列表中确认它已经出现。

项目结束时按顺序处理：

1. 下载需要保留的文件和最终成果；
2. 检查共享成员是否已经保存必要资料；
3. 移除不再需要的成员或关闭链接共享；
4. 删除不应继续保留的来源文件；
5. 确认不需要任何聊天和指令后，再选择 **Delete project**。

删除 Project 会永久删除其中的文件、聊天和项目指令，且无法撤销。OpenAI 当前说明，删除的数据通常会在 30 天内从系统移除，法律或安全要求需要继续保留的情况除外。

## 常见故障快速判断

| 症状 | 最可能的原因 | 下一步 |
|---|---|---|
| 看不到 New project | App 版本、账号开放状态或工作区管理员限制 | 先用网页版同一账号检查，再联系工作区管理员或 OpenAI |
| 文件上传按钮不可用 | 项目文件已满、单次上传过多或服务异常 | 核对文件数量，减少批次并查看 OpenAI Status |
| 回答没有使用项目文件 | 文件未成功加入、问题范围不明确或资料无法读取 | 打开来源列表确认文件，再要求回答标注文件名和日期 |
| 找不到 Move to project | 聊天来自 GPT、属于 Temporary Chat 或当前聊天不符合移动条件 | 在项目内新建聊天并只迁移必要背景 |
| Project memory 没有生效 | Memory 设置未开启，或刚修改仍在生效中 | 检查 Personalization 设置，等待后用新聊天重新测试 |
| 分享对象无法访问 | 邀请账号错误、链接范围受限或工作区管理员关闭共享 | 核对邀请邮箱、Share 设置和工作区权限 |
| 项目内没有 Deep Research 或其他工具 | 当前计划不含该工具，或工作区管理员禁用 | 先核对计划和工作区设置，不要重复购买 |
| 项目显示 Free 或付费权益缺失 | 登录了其他账号，或会员权益没有显示在当前登录账号上 | 先处理[已付款仍显示 Free]({{ '/guides/chatgpt-paid-but-still-free/' | relative_url }})问题 |

## Free、Plus 和 Pro 应该怎样判断

Projects 本身并不是付费专属功能。Free 用户也可以创建项目、添加文件和共享协作，只是当前文件和协作者上限更低。

只有同时满足以下条件时，才需要考虑升级：

1. 当前账号没有有效订阅、成功扣款或待处理交易；
2. 已经确认任务超过 Free 的文件或协作者上限，或确实需要某项付费工具；
3. 已经阅读 OpenAI 当前计划说明，并确认目标功能对该计划开放。

满足上述条件后，可以在 [ChongGrok ChatGPT 页面](https://chonggrok.com/chatgpt?utm_source=github_guides&utm_medium=referral&utm_campaign=chatgpt_projects_guide)查看当前 Plus、5x Pro 和 20x Pro 方案。已有扣款、交易待处理或有效订阅时，应先排查账号和付款状态，不要再次购买。

## 隐私与安全边界

- 不向 Project 上传密码、邮箱或短信验证码、恢复码、银行卡资料或 ChatGPT session；
- 共享项目中的成员可以查看和下载文件，添加成员前必须完成脱敏；
- Free、Plus 和 Pro 账号如果开启 **Improve the model for everyone**，项目数据可能用于改进模型；
- Business、Enterprise 和 Edu 的项目数据默认不用于训练模型；
- 共享项目只有在所有贡献者和所有者都允许时，数据才可能用于训练；
- 外部 App 仍受对应第三方的权限和数据政策约束，连接前应确认账号和授权范围；
- 任何线上服务都不是零风险，Project 不能替代本地备份、访问控制和人工复核。

## 完成验收清单

- [ ] 项目名称能够说明用途；
- [ ] 记忆范围与资料敏感程度一致；
- [ ] 项目指令写清目标、资料优先级和输出格式；
- [ ] 每个文件都已打开并核对；
- [ ] 第一次测试回答正确引用项目资料；
- [ ] 共享权限按 Chat 或 Edit 正确分配；
- [ ] 项目中没有密码、验证码、恢复码或其他不必要的敏感信息；
- [ ] 删除项目之前已经保存最终成果。
